1. RESPOSTA DIRETA (o comando)
------------------------------------------------------------------------
A rota /api/v1/dominios/unidades/ e publica (nao pede token), nao
pagina e devolve uma lista JSON pura. Entao e so isso:

    curl -s "$BASE/api/v1/dominios/unidades/" -o unidades.json

Para nao salvar um arquivo silenciosamente errado, prefira a versao
com -f (explico na secao 4) e confira o status:

    curl -sSf "$BASE/api/v1/dominios/unidades/" -o unidades.json \
      -w "status=%{http_code} bytes=%{size_download}\n"

------------------------------------------------------------------------
2. SAIDA REAL (executado agora, nao e exemplo inventado)
------------------------------------------------------------------------
    $ curl -s -o unidades.json -w "status=%{http_code} bytes=%{size_download}\n" \
        "$BASE/api/v1/dominios/unidades/"
    status=200 bytes=125

    $ cat unidades.json
    [{"id":2,"sigla":"ILE","nome":"Instituto de Letras"},
     {"id":1,"sigla":"IME","nome":"Instituto de Matemática e Estatística"}]

(na saida real e uma linha so, sem quebra; quebrei aqui so para ler.)

Os acentos vem certos: o corpo ja e UTF-8 com "Matemática e
Estatística" escrito por extenso, nao como \uXXXX. O header e
"Content-Type: application/json" (sem charset), o que na pratica nao
atrapalha jq nem python.

Repare tambem na ordem: a API devolve ILE antes de IME, ou seja,
ordenado por sigla, porque o model tem Meta.ordering = ['sigla']
(core/models.py:23). Nao e ordem de id.

3. ATENCAO: "todas" aqui nao e literalmente todas
------------------------------------------------------------------------
Essa rota so devolve unidades com ativo=True, porque o queryset e

    core/views.py:55

Conferi o banco agora: total 2, ativas 2, inativas 0. Ou seja, hoje o

Se o que voce quer e o cadastro completo, incluindo inativas, pule para
a secao 10 (dumpdata), que traz todas.

------------------------------------------------------------------------
4. SALVAR EM ARQUIVO SEM PEGAR LIXO
------------------------------------------------------------------------
Pegadinha do curl: o -o grava no arquivo o corpo da resposta mesmo
quando ela e um erro. Testei com um id inexistente:

    # sem -f: o arquivo fica com o JSON de erro e o curl "da certo"
    $ curl -s -o erro.json -w "status=%{http_code}\n" \
        "$BASE/api/v1/dominios/unidades/9999/"
    status=404
    $ cat erro.json
    {"detail":"No UnidadeAcademica matches the given query."}

    # com -f: o curl falha e nem cria o arquivo
    $ curl -s -f -o erro.json -w "status=%{http_code}\n" \
        "$BASE/api/v1/dominios/unidades/9999/"
    status=404
    $ echo $?
    22
    $ test -f erro.json && echo existe || echo "arquivo nao foi criado"
    arquivo nao foi criado

Por isso o certo e -sSf: o -f (--fail) aborta em HTTP >= 400 com exit
22 e o -S mostra a mensagem de erro em vez de engolir. Um script seguro
para salvar fica assim:

    set -euo pipefail
    BASE=http://127.0.0.1:8000
    curl -sSf "$BASE/api/v1/dominios/unidades/" -o unidades.json
    jq -e . unidades.json > /dev/null && echo "JSON valido: $(jq length unidades.json) unidades"

O jq -e . e a validacao barata: se o arquivo estiver truncado ou vier
HTML de pagina de erro, o jq falha e o && nao deixa passar.

Sobre onde salvar: o .gitignore deste repo so tem .vercel, .env.local e
.env, entao unidades.json na raiz apareceria como arquivo novo no git
status. Se for dado de teste, jogue em /tmp ou num diretorio de dados e
adicione ao .gitignore.

5. DEIXAR O JSON LEGIVEL
------------------------------------------------------------------------
O arquivo salvo e JSON valido, so que numa linha. Para indentar, as
duas opcoes que testei:

    jq . unidades.json                    # indentado com 2 espacos

Para gravar a versao legivel em outro arquivo:

    python3 -m json.tool unidades.json > unidades-formatado.json

E para voltar a uma linha (util para comparar com diff ou commitar):

6. RECEITAS jq QUE EU RODEI NESSA LISTA
------------------------------------------------------------------------
Todas abaixo foram executadas no arquivo salvo, com o resultado real:

    $ jq length unidades.json
    2

    $ jq -r '.[].sigla' unidades.json
    ILE
    IME

    $ jq -r '.[] | "\(.id) \(.sigla) \(.nome)"' unidades.json

Outras uteis no mesmo estilo (mesma logica, nao rodei uma a uma):

    jq -r '.[] | [.sigla, .nome] | @csv' unidades.json
    jq -r 'map(.id) | @csv' unidades.json

7. PAGINACAO E TOKEN NESSA ROTA
------------------------------------------------------------------------
Paginacao: desligada. O LookupViewSet, de onde herdam todos os dominios,
faz pagination_class = None (core/views.py:51). Testei com ?page=2 e
veio a lista inteira de novo, sem envelope de count/next/results:

    $ curl -s "$BASE/api/v1/dominios/unidades/?page=2"
    [{"id":2,...},{"id":1,...}]   [200]

Ou seja: nessa rota nao existe "pagina 2", o JSON e sempre a lista
completa. Nao precisa de loop de paginas.

Token: essa rota e AllowAny (core/views.py:50), entao nao pede
Authorization. Confirmei o 200 sem mandar header nenhum. Se voce quiser
padronizar com as rotas que pedem token, e so mandar o Bearer - o login
da API usa CPF, nao e-mail:

    TOKEN=$(curl -s -X POST "$BASE/api/v1/auth/login/" \
      -H "Content-Type: application/json" \
      -d '{"cpf":"123456789","password":"SUA_SENHA"}' | jq -r .access)

    curl -sSf -H "Authorization: Bearer $TOKEN" \
      "$BASE/api/v1/dominios/unidades/" -o unidades.json

(o login em si eu nao testei com credencial valida; o que esta
verificado e que o payload e {"cpf","password"} e que este GET funciona
sem token.)

10. QUER O CADASTRO COMPLETO (INCLUSIVE INATIVAS)? DUMPDATA
------------------------------------------------------------------------
Se o objetivo e ter as unidades de verdade, todas, do jeito que estao no
banco, a API nao serve por causa do filtro ativo=True. O caminho e o
dumpdata do Django, que fala direto com o banco:

    cd backend
    .venv/bin/python manage.py dumpdata core.UnidadeAcademica \
      --indent 2 -o unidades-completas.json

Saida real do arquivo (rodei agora):

    [
    {
      "model": "core.unidadeacademica",
      "pk": 1,
      "fields": { "sigla": "IME",
                  "nome": "Instituto de Matemática e Estatística",
                  "ativo": true }
    },
    {
      "model": "core.unidadeacademica",
      "pk": 2,
      "fields": { "sigla": "ILE",
                  "nome": "Instituto de Letras",
                  "ativo": true }
    }
    ]

Diferencas em relacao a API:
  - traz o campo "ativo" e o "pk";
  - nao tem o filtro de ativo, entao sao realmente todas;
  - a ordem observada foi por pk (1, 2), nao por sigla - se precisar
    ordenado, jq 'sort_by(.fields.sigla)';
  - o formato e o de fixture do Django: --indent 2 e o mesmo arquivo que
    o loaddata consome. Ou seja, isso serve de backup/seed:
    .venv/bin/python manage.py loaddata unidades-completas.json
    (o loaddata eu NAO rodei, porque grava no banco.)
  - precisa de acesso ao banco (DATABASE_URL no .env); sem isso o
    comando falha, enquanto o curl na API nao precisa de banco local.

Sem -o, o dumpdata imprime no stdout, entao tambem vale
    ... dumpdata core.UnidadeAcademica --indent 2 | jq -c '.[].fields'
